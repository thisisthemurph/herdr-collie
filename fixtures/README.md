# fixtures

Test data for every contract. Placeholders only: `[SITE]`, `[WORKSPACE]`, `[REPO]`, `[MODEL]`.

| Folder | What |
| --- | --- |
| `inbox/{valid,invalid}/` | One inbox line per file: every agent event type, valid and invalid |
| `events/{valid,invalid}/` | One `events.jsonl` line per file: every controller event type |
| `files/<kind>/{valid,invalid}/` | Profiles, workflows, boards, `run.json`, `execution.json`, `state.json`, control commands and replies |
| `runs/complete/` | `events.jsonl`, `run.json` and `executions/` for one complete two-ticket run |
| `hc/` | Recorded output of real `hc`, used by `tools/fake-hc` tests (hand-written, not generated) |
| `home/` | A `COLLIE_HOME` in mid-run (remediation), for `collie show task/findings/answers` |
| `boards/` | Boards of many shapes (chain, diamond, long edges, outside blockers, a cycle, a random 40-ticket DAG, the spike's 20 nodes) for the graph and layout tests |
| `jira/` | Recorded Jira traffic, scrubbed (`[SITE]`, `[CLOUD-ID]`, `TST-n` keys), played back by `packages/controller/test/jira.test.ts`. Recorded with `tools/jira-record` (hand-run, reads the `collie-jira` keychain item); not generated |
| `scenarios/` | fake-agent scenarios and the inbox each must produce; `controller-inbox.jsonl` and the events the controller must log for it (hand-written, not generated) |

Each `invalid/expected.json` maps a file to the field its error must name (`""` for a
whole-line problem such as a missing newline).

Everything except `hc/`, `jira/` and `scenarios/` is generated by `fixtures/src/build.ts`. After a schema change,
edit that script and run `make fixtures`. A test fails if the committed files differ from
its output.

`scenarios/*.expected.jsonl` are compared with generated ids and timestamps ignored. To
re-record after an intended change, run the test with `UPDATE_EXPECTED=1` (`packages/cli`
for the fake-agent scenarios, `packages/controller -t "fixture inbox"` for the controller
one), then review the diff.
